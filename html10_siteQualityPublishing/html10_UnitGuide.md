# html10 — Site Quality & Publishing · Unit Guide

**The merged quality unit (formerly html12 SEO & Accessibility + html13 Testing, Protocols & Publishing), rebuilt per the v2 master plan. This is the vocabulary unit — most of the written-exam-only surface lives here.**

**ODE competencies:** 6.5.14 (SEO) · 6.1.2, 2.7.4 (ADA/screen readers) · 6.1.4 (proofreading) · 6.5.1 (standards & protocols) · 2.7.2, 2.7.5, 2.7.6, 2.7.8 (architecture) · 6.5.10, 6.5.11 (testing) · 6.5.12 (publish) · 6.5.4 (CMS, describe level) · 2.11 (troubleshooting, introduced)

## How this unit runs (≈5 class periods)

| Segment | Content | Materials |
|---|---|---|
| 10a | SEO: titles, meta descriptions, headings, alt, keywords | html10_SeoSlides, html10_SeoWalkthrough, html10a_Task |
| 10b | Accessibility: ADA, screen readers, keyboard nav, contrast, `aria-label` | html10_SeoSlides (2nd half), html10b_Task |
| 10c | Protocols & architecture: FTP/TCP-IP/HTTP, static vs dynamic, **bandwidth & latency, plug-ins, CMS** (new topics), ways to present data | html10_PublishSlides, **html10_NewTopicsSlides**, html10c_Task |
| 10d | Testing: cross-browser/device, usability checklist, W3C validator; troubleshooting methodologies introduced (drilled in html12) | html10_PublishWalkthrough, html10d_Task |
| 10e | Publish to GitHub Pages — GitHub Desktop flow, no CLI | html10e_Task, html10_PublishDIYTask |

## Scope decisions (from the master plan — don't drift)

- **CLI git is cut.** The class runs GitHub Desktop; the publish materials teach commit-then-push through it. Terminal commands get one "you'll see these online" aside, nothing more.
- **ARIA is `aria-label` only.** The attribute catalog is beyond both exams.
- **CMS is describe level here** (what a CMS is, static vs CMS-driven, WordPress as the big example). Students *configure* a real one hands-on in html11's builder segment.

# html11d — The Builder Builds

Two builds, one day-and-a-half, zero code. The point isn't that these tools are easy — it's understanding exactly WHAT they trade away for easy, which you can only see because you've done it the hard way.

## Build 1: Google Sites (~45 minutes, deliberately quick)

1. sites.google.com → new site for your client
2. Recreate your home page and one other: header, nav, text, images
3. Publish it. Note the URL.

While you work, keep a running list: what was faster than hand-coding? What did you WANT to do that Sites simply wouldn't let you? (Try to add your dark mode. Try to control exactly where an image sits.)

## Build 2: WordPress.com — a real CMS (competency 6.5.4)

WordPress powers ~40% of the web. The free tier at wordpress.com skips the install (that's the "hosted" part — remember the html10 slide on what installing involves) and drops you straight into *configuring* a CMS:

1. Create a free site for your client
2. Pick a **theme** — notice: the theme is a template system; your content pours into it
3. Build your pages, set up the **menu** (navigation), add a **post** (the announcement/news feature your client needed — this is the thing static sites can't give a non-coder)
4. Poke the dashboard: users/roles, themes, the plugin directory (look, don't install). Connect what you see to the html10 CMS slide's vocabulary
5. Publish; note the URL

## The comparison notes (feed segment 11f)

For each builder, record in your working notes: build time, what the client's non-coder secretary could maintain alone, what's impossible that your hand-coded site does, what it costs to remove ads/get a real domain, and — for WordPress — where the database + template structure showed itself.
